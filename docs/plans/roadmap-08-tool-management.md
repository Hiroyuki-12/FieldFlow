# ロードマップ8 道具管理 実装計画

## 1. 目的

チームが保有する道具、所属する作業カテゴリ、在庫数を安全に管理できるようにし、後続の日別チェック作成が参照する道具マスターを完成させる。

道具は過去の日別チェック項目から参照されるため物理削除せず、利用停止と再有効化で運用する。在庫数は保有総数であり、日別の持ち出し数によって増減させない。

対応Issueは [#23 ロードマップ8 道具管理機能を実装する](https://github.com/Hiroyuki-12/FieldFlow/issues/23) とする。

## 2. Backend実装

### 2.1 API

| Method / Path | 権限 | 概要 |
| --- | --- | --- |
| `GET /api/v1/tools` | 全ログインユーザー | 名前検索、カテゴリ・状態絞り込み、ページング |
| `POST /api/v1/tools` | `ADMIN` | 道具作成 |
| `GET /api/v1/tools/:id` | 全ログインユーザー | 道具詳細取得 |
| `PATCH /api/v1/tools/:id` | `ADMIN` | 名前、カテゴリ、在庫数、表示順更新 |
| `PATCH /api/v1/tools/:id/status` | `ADMIN` | 利用停止・再有効化 |

ControllerはHTTP入出力と権限制御を担当し、入力の正規化、名称重複、カテゴリ状態、更新競合はServiceへ集約する。

### 2.2 入力とレスポンス

- 名前は前後空白を除去し、1〜100文字とする。
- `categoryId`はUUIDかつ有効なカテゴリを必須とし、`WORK`と`COMMON`の両方を許可する。
- 在庫数と表示順は0〜9999の整数とする。
- 更新・状態変更は画面が保持する`version`を必須とし、古い値は`409 TOOL_UPDATE_CONFLICT`で拒否する。
- 一覧は1始まりの`page`、既定20・最大100の`pageSize`を受け取る。
- 一覧はカテゴリ表示順、道具表示順、道具名、道具IDの順に並べ、同順位でも結果を安定させる。
- レスポンスにはカテゴリ名・カテゴリ種別・カテゴリ状態を含め、画面がRelation構造や追加APIに依存しないようにする。

### 2.3 セキュリティと整合性

- 名称はMySQLの大文字小文字を区別しない一意制約を最終防壁とし、違反を`409 TOOL_NAME_DUPLICATED`へ変換する。
- 作成とカテゴリ移動ではTransaction内で対象カテゴリ行を悲観ロックし、有効状態を確認してから道具を保存する。
- 無効カテゴリの指定は`422 CATEGORY_INACTIVE`、存在しないカテゴリは`404`で拒否する。
- 更新と状態変更では対象道具行をTransaction内で悲観ロックし、version確認後に保存する。
- 同じ状態への再送はversionを進めず現在値を返す。
- 利用停止後も物理削除せず、既存の日別チェックと監査可能性を維持する。

## 3. Frontend実装

- 全ログインユーザー向けRoute`/tools`と、PC・モバイルのナビゲーションを追加する。
- 名前検索、カテゴリ・状態絞り込み、ページングを提供し、道具をレスポンシブなカード形式で表示する。
- カテゴリ選択肢は道具一覧APIの`categories`から取得し、作成・編集では有効カテゴリだけを選択可能にする。
- 管理者には作成・編集・利用停止・再有効化ダイアログを表示し、作業者には変更操作を表示しない。
- 在庫数と表示順は数値入力とし、0〜9999の範囲をFrontendでも検証する。
- APIの業務エラーコードを、利用者が次の対応を判断できる日本語メッセージへ変換する。
- ダイアログを閉じた後は操作元へフォーカスを戻し、キーボード操作と360px幅を考慮する。

## 5. 実装順序

1. 公開レスポンス型とDTOを用意する。
2. ToolsServiceへ一覧・作成・詳細・編集・状態変更を実装する。
3. ToolsControllerとToolsModuleを追加し、単体・結合テストを通す。
4. FrontendのTool API Clientと全ログインユーザー向けRouteを追加する。
5. カード一覧、検索、ページング、管理者用ダイアログを実装する。
6. Frontend API・画面テストと全品質チェックを実行する。
7. 実MySQL、NestJS、Vueを標準portで接続し、管理者と作業者の主要操作を確認する。

## 8. 実装結果

2026-08-16にIssue #23の計画作成、実装、自動テストを完了した。

### 8.1 Backend

- `ToolsModule`、Controller、Service、4 DTO、公開レスポンス型を追加し、TOOL-01〜05の5 APIを実装した。
- 一覧・詳細は全ログインユーザーへ公開し、作成・編集・状態変更だけを`ADMIN`限定にした。
- 一覧へ名前・カテゴリ・状態の絞り込み、1始まりページング、カテゴリ表示順→道具表示順→名前→IDの安定した並び順を実装した。
- 現在ページに道具がないカテゴリも絞り込み・管理フォームで使えるよう、一覧レスポンスへ全カテゴリの選択肢を含めた。
- 作成・編集・再有効化ではカテゴリ行を悲観ロックし、有効確認から道具保存までの間にカテゴリが停止される競合を防止した。
- 更新と状態変更では道具行を悲観ロックし、画面が保持する`version`と比較して古い更新を`TOOL_UPDATE_CONFLICT`で拒否した。
- MySQLの一意制約違反を`TOOL_NAME_DUPLICATED`、無効カテゴリを`CATEGORY_INACTIVE`へ変換した。
- 同じ状態への再送はversionを進めず、道具を物理削除しない運用を維持した。

### 8.2 Frontend

- 全ログインユーザー向け`/tools` Routeと、PC・モバイル・サイドバーのナビゲーションを追加した。
- 名前検索、カテゴリ・状態絞り込み、ページング、カテゴリ名・保有数・表示順・状態を示すカード一覧を追加した。
- 管理者には作成・編集・利用停止・再有効化ダイアログを表示し、作業者には変更操作を表示しないようにした。
- 管理フォームでは停止中カテゴリを選択不可にし、名前、在庫数、表示順をFrontendでも検証した。
- 名称重複、更新競合、無効カテゴリを、次の対応が分かる日本語メッセージへ変換した。
- ダイアログの初期フォーカスと操作元へのフォーカス復帰、44px以上の操作領域、360px幅で折り返すカード・フォーム配置を実装した。
