# ロードマップ7 作業カテゴリ管理 実装計画

## 1. 目的

管理者が「草取り」「洗車」などの作業カテゴリを安全に管理できるようにし、後続の道具管理と日別チェック作成が参照できるマスターを完成させる。

カテゴリは過去の日別表から参照されるため物理削除せず、利用停止と再有効化で運用する。Seedで作成した`COMMON`カテゴリは、すべての日別表へ共通道具を追加する基準になるため、通常カテゴリより強く保護する。

対応Issueは [#19 ロードマップ7 作業カテゴリ管理機能を実装する](https://github.com/Hiroyuki-12/FieldFlow/issues/19) とする。

## 2. Backend実装

### 2.1 API

| Method / Path | 概要 |
| --- | --- |
| `GET /api/v1/categories` | 名前検索、状態絞り込み、一覧取得 |
| `POST /api/v1/categories` | `WORK`カテゴリ作成 |
| `GET /api/v1/categories/:id` | カテゴリ詳細取得 |
| `PATCH /api/v1/categories/:id` | 名前、表示順更新 |
| `PATCH /api/v1/categories/:id/status` | 利用停止・再有効化 |

全APIをJWT認証かつ`ADMIN`限定とする。ControllerはHTTP入出力を担当し、入力の正規化、重複判定、更新競合、`COMMON`保護、使用中判定はServiceへ集約する。

### 2.2 入力とレスポンス

- 名前は前後空白を除去し、1〜50文字とする。
- 表示順は0〜9999の整数とする。
- 作成時の`categoryType`はBackendが`WORK`へ固定し、クライアントから`COMMON`を指定させない。
- 更新・状態変更は画面が保持する`version`を必須とし、古い値は`409 CATEGORY_UPDATE_CONFLICT`で拒否する。
- 一覧は`displayOrder`、名前、IDの順に並べ、同順位でも結果を安定させる。
- レスポンスはID、名前、表示順、種別、状態、version、作成・更新日時だけを返す。

### 2.3 セキュリティと整合性

- 名称はMySQLの大文字小文字を区別しない一意制約を最終防壁とし、違反を`409 CATEGORY_NAME_DUPLICATED`へ変換する。
- 更新と状態変更では対象カテゴリ行をTransaction内で悲観ロックし、version確認後に保存する。
- `COMMON`カテゴリは名称変更と利用停止を`409 COMMON_CATEGORY_PROTECTED`で拒否する。表示順の変更と再有効化は許可する。
- 有効な道具が1件以上紐づくカテゴリの利用停止は`409 CATEGORY_IN_USE`で拒否する。無効な道具だけなら停止できる。
- 同じ状態への再送はversionを進めず現在値を返す。
- 後続の道具作成・移動では同じカテゴリ行をロックして有効状態を確認し、「使用中確認の直後に有効な道具が追加される」競合を防ぐ。

## 3. Frontend実装

- 管理者専用Route`/categories`と、PC・モバイルの管理ナビゲーションを追加する。
- 名前検索と状態絞り込みを提供し、カテゴリをレスポンシブなカード形式で表示する。
- 作成・編集・利用停止・再有効化を画面内ダイアログから操作する。
- `COMMON`カテゴリには用途説明を表示し、名称入力を無効化して利用停止操作を表示しない。ただし最終的な拒否はBackendで行う。
- 表示順は数値入力とし、0〜9999の範囲をFrontendでも検証する。
- APIの業務エラーコードを、利用者が次の対応を判断できる日本語メッセージへ変換する。
- ダイアログを閉じた後は操作元へフォーカスを戻し、キーボード操作と360px幅を考慮する。

## 4. テスト計画

### Backend単体テスト

- 一覧条件と並び順、作成、詳細、編集、状態変更
- 名称重複、404、古いversion、`COMMON`名称変更・利用停止
- 有効な道具があるカテゴリの停止拒否と、無効な道具だけの場合の停止許可
- 作業者に対するRole Guardの403

### Backend結合テスト

- ControllerからTypeORM、MySQLまでを通した5 API
- 実DBの大文字小文字を区別しない一意制約と並び順
- Transaction、悲観ロック、楽観的なversion競合、使用中判定、`COMMON`保護
- 未認証401、作業者403、入力不正400、404、409

### Frontendテスト

- カテゴリAPIのMethod、URL、Query、Body
- 一覧、検索、状態絞り込み
- 作成、編集、利用停止・再有効化
- `COMMON`カテゴリの説明と保護対象操作の非表示／無効化
- 名称重複、使用中、競合、通信失敗の表示
- 作業者の管理Route拒否と管理ナビゲーション非表示

## 5. 実装順序

1. 公開レスポンス型とDTOを用意する。
2. CategoriesServiceへ一覧・作成・詳細・編集・状態変更を実装する。
3. CategoriesControllerとCategoriesModuleを追加し、単体・結合テストを通す。
4. FrontendのCategory API Clientと管理Routeを追加する。
5. カード一覧、検索、作成・編集・状態変更ダイアログを実装する。
6. Frontend API・画面テストと全品質チェックを実行する。
7. 実MySQL、NestJS、Vueを標準portで接続し、主要操作を確認する。
