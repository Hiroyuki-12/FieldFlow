# ロードマップ10 ホーム・日別表表示 実装計画

## 1. 目的

ロードマップ9で実装した日別表の作成・取得APIをVue画面へ接続し、管理者と作業者がホームから今日・別日の日別表を作成・閲覧できるようにする。

対応Issueは [#27 ロードマップ10 ホーム・日別表表示を実装する](https://github.com/Hiroyuki-12/FieldFlow/issues/27) とする。

## 2. Frontend実装

### 2.1 API Clientと日付

- `GET /api/v1/daily-checklists/:date`で指定日の作成済み表を取得する。
- `PUT /api/v1/daily-checklists/:date`へ作成方式と全時間帯を1回で送り、BackendのTransactionと冪等性を利用する。
- 作成候補は、全ログインユーザーが閲覧できる道具一覧レスポンスの`categories`から、有効な`WORK`だけを抽出する。管理者用カテゴリAPIの権限を広げない。
- 「今日」はBackendと同じAsia/Tokyoで求め、UTCや端末設定による日付境界のずれを防ぐ。

### 2.2 ホーム

- 初期表示で今日の日別表を取得する。`CHECKLIST_NOT_FOUND`は異常終了ではなく未作成状態として扱う。
- 作成済みの場合は時間帯、持ち出し数が1以上の項目を分母とした準備進捗、「今日のチェックを開く」を表示する。
- 未作成の場合は「今日のチェックを作成」から作成ダイアログを開く。
- 別日の日付入力から日別チェック画面へ移動する。
- 管理者には道具、作業カテゴリ、ユーザー管理へのショートカットを表示する。

### 2.3 作成ダイアログ

- `FULL_DAY`では1組、`SPLIT`では午前と午後を別々に選択する。
- `SPLIT`の時間帯タブを切り替えても選択を保持し、両時間帯で1件以上のカテゴリを必須とする。
- 共通カテゴリは利用者に選ばせず、Backendが共通道具を自動追加することを説明する。
- 見出しと操作ボタンを固定し、カテゴリ部分だけをスクロールさせる。
- 404、409、422と通信失敗を、次の対応が分かる日本語へ変換する。

### 2.4 日別チェック画面

- `/daily-checklists/:date`を全ログインユーザー向けRouteとして追加する。
- 日付変更と今日へ戻る操作を提供する。
- `SPLIT`は午前・午後を切り替え、それぞれのカテゴリ・道具・進捗を独立して表示する。
- カテゴリ名、道具名、在庫数、持ち出し数、準備状態をBackendのスナップショットレスポンスから表示する。
- 過去日の作成済み表は閲覧専用、未作成日は表なしとして表示し、作成ボタンを出さない。
- 数量・チェック更新がまだ未接続であることを画面に明示する。

### 2.5 登録間違いの修正・削除

- 今日・未来日は`時間帯・作業内容を変更する`と`この日のチェック表を削除する`を表示する。過去日には表示しない。
- 設定変更では現在の方式・時間帯別カテゴリを初期表示する。入力済み内容がある場合は、同じ時間帯・同じ道具だけを引き継ぐことを説明して再確認する。
- 削除では持ち出し数・準備状態への影響と、削除後に同日再作成できることを確認ダイアログで説明する。
- Backendでは物理削除せず、旧版を`CANCELLED`として保持する。`ACTIVE`版だけを1日1件に制限し、設定変更・削除の実行者と時刻を保存する。
- ヘッダーIDとversionで別利用者による先行変更を検知し、古い画面からの操作を409で拒否する。

## 3. テスト計画

- APIのGET／PUT URL、Method、Bodyを確認する。
- カテゴリ候補から有効な`WORK`だけを抽出することを確認する。
- ホームの作成済み時間帯、準備進捗、未作成時の作成導線、別日遷移を確認する。
- `SPLIT`で午前・午後の選択を保持し、全時間帯を1回のPUTで送ることを確認する。
- 日別チェック画面で午前・午後のカテゴリと道具が混ざらないことを確認する。
- 過去日の表なしと、作成済み表の閲覧専用表示を確認する。
- RouterとPC・モバイル・サイドバーのナビゲーションを回帰確認する。
- 設定変更の初期値、入力済み警告、PATCH本文、削除確認、DELETE本文、削除後の再作成導線を確認する。
- Testcontainers MySQLで旧版保持、同じ時間帯・同じ道具の入力引継ぎ、削除後の再作成、古いversion拒否を確認する。

## 7. 実装結果

2026-08-19にIssue #27の計画作成、Frontend・Backend・DB実装、自動テスト、標準ポートでの疎通確認を完了した。

### 7.1 Frontend

- 日別表の取得・作成型とAPI Client、Asia/Tokyo基準の日付Utilityを追加した。
- 管理者用カテゴリAPIを作業者へ開放せず、全ユーザー向け道具一覧に含まれるカテゴリ候補から有効な`WORK`だけを利用した。
- ホームを今日の未作成・持ち出し未設定・準備中・準備完了へ対応させ、別日選択と管理者ショートカットを追加した。
- 共通の作成ダイアログを追加し、`FULL_DAY`または`SPLIT`のカテゴリを保持して全時間帯を1回のPUTで作成するようにした。
- 日別チェックRouteと画面を追加し、日付変更、午前・午後切替、進捗、カテゴリ・道具・在庫・持ち出し数・準備状態を表示した。
- 過去日の作成済み表は閲覧専用、未作成日は作成不可として表示した。
- PC、モバイル、サイドバーへ日別チェックのナビゲーションを追加した。
- 今日・未来日の設定変更と表削除を追加した。設定変更前・削除前の版は取消履歴として保持し、削除後は同日へ再作成できる。
- 数量・チェック更新、自動保存、カテゴリ追加、項目単位の楽観ロックはロードマップ11の責務として未実装である。

### 7.2 Backend・DB

- `PATCH /daily-checklists/:date/configuration`を追加し、現行版をロックして旧版の取消と新版の作成を1トランザクションで行うようにした。
- 同じ時間帯・同じ道具だけ入力値を引き継ぎ、在庫上限を超える数量は安全に未設定へ戻すようにした。
- `DELETE /daily-checklists/:date`を追加し、利用者には削除として提供しながらDBでは`CANCELLED`履歴を保持するようにした。
- `status`、`active_work_date`、取消実行者・時刻、ヘッダー`version`を追加するMigrationを作成した。一意制約とCHECK制約により、取消履歴を複数残しながら現行版を1日1件へ限定した。
- 入力済み内容への影響確認と、ヘッダーID・versionによる古い画面からの上書き防止をAPIでも必須にした。
