# 日付別チェック機能定義

## 目的

特定日に持ち出す道具の数と準備状態をチームで共有し、道具忘れと確認漏れを減らす。

## 正常系: 表の生成

- 1チームにつき1日1件とし、`workDate`へ一意制約を付ける。
- 今日・未来日は`PUT`で冪等に作成する。同じ日への同時作成は一意制約とトランザクションで1件へ収束させる。
- 初回生成時の全有効道具を日別項目へ複製し、道具名、カテゴリ名、在庫数をスナップショット保存する。
- 過去日に表がなければ`GET`は`404 CHECKLIST_NOT_FOUND`を返し、暗黙作成しない。

## 表の操作

- 管理者と作業者は日付選択、閲覧、今日・未来日の持ち出し数・チェック状態更新を行える。
- 更新は行単位で自動保存し、成功時に更新後の`version`を返す。
- 管理者は有効な道具を作成済みの今日・未来日の表へ手動追加できる。
- 同じ道具は同じ表へ1回だけ追加できる。

## 入力・状態ルール

| 項目 | ルール |
| --- | --- |
| takeoutQuantity | 0〜`stockQuantitySnapshot`の整数 |
| checked | 数量1以上のときだけ`true`可 |
| 数量を0へ変更 | 同一トランザクションで`checked=false` |
| 過去日 | 閲覧のみ、作成・追加・更新不可 |
| version | リクエスト値とDB値が一致するときだけ更新 |

## 競合時の扱い

- バージョン不一致は`409 CHECKLIST_ITEM_UPDATE_CONFLICT`とし、`details.currentItem`に最新行を含める。
- フロントは編集中の値を破棄して最新行を表示し、「他のユーザーが更新しました」と通知する。
- MVPでは自動マージやリアルタイムPush配信を行わない。別ユーザーの更新は再取得・再訪時に反映する。

## 異常系

- 過去日の作成・追加・更新、在庫超過、数量0でのチェックは`422`とする。
- 存在しない日別表・項目・道具は`404`とする。
- 作業者による道具追加は`403`、同一道具の重複追加は`409`とする。
- 通信失敗時は画面上の値を「保存済み」と扱わず、再試行できる状態を表示する。

## 受け入れ条件

- マスター変更後も作成済みの表の名称・カテゴリ・上限数が変わらない。
- 在庫超過、0件でのチェック、過去日更新、重複追加がAPIで拒否される。
- 作業者は項目を更新できるが、道具追加はできない。
