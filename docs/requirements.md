# FieldFlow MVP 要件定義

## 1. 目的

FieldFlow は、現場作業前の道具忘れと紙のチェック漏れを減らすためのチーム共有型Webアプリケーションである。MVPでは、認証・ユーザー管理・道具マスター管理・日付別チェックに対象を絞り、誰がどの権限で何を操作できるかを明確にする。

## 2. 利用者と利用範囲

- MVPは1チーム固定とし、登録された全ユーザーが同じ道具マスターと日別チェック表を共有する。
- UIは日本語、業務上の日付判定は`Asia/Tokyo`、DBの日時はUTCで保存する。
- 現場のスマートフォンを優先し、管理者がPCでも操作できるレスポンシブUIとする。

| ロール | 主な責任 |
| --- | --- |
| 管理者（`ADMIN`） | ユーザー、カテゴリ、道具マスターの管理と日別表への道具追加 |
| 作業者（`WORKER`） | 道具一覧の確認と日別チェックの入力 |

## 3. MVP機能要件

### 3.1 認証

- ログインIDとパスワードでログインできる。
- Access TokenとRefresh Tokenを使用し、未認証ユーザーは業務画面を利用できない。
- 初期管理者は一回限りのSeedで作成する。
- 管理者がユーザーを作成・再発行したとき、16文字の仮パスワードを一度だけ表示する。
- 仮パスワード利用者は初回ログイン後、他機能を使う前にパスワードを変更する。
- ログアウト、パスワード変更、ユーザー利用停止時は対象セッションを失効させる。

### 3.2 ユーザー管理

- 管理者はユーザーの一覧、作成、名前・ログインID・ロールの編集、利用停止、仮パスワード再発行ができる。
- ユーザーは物理削除せず、`ACTIVE` / `INACTIVE`で管理する。
- 最後の有効な管理者、自分自身の利用停止、自分自身を作業者へ変更する操作は拒否する。

### 3.3 カテゴリ管理

- 管理者はカテゴリの一覧、作成、名称・表示順の編集、利用停止、再有効化ができる。
- 有効な道具が紐づくカテゴリの利用停止は拒否する。
- カテゴリ名は前後空白を除去し、大文字小文字を区別せず一意とする。

### 3.4 道具マスター管理

- 道具項目は、名前、在庫数、カテゴリ、状態、表示順を持つ。
- 管理者は道具の一覧、作成、編集、利用停止、再有効化ができる。
- 作業者は道具マスターを閲覧できるが変更できない。
- 道具名は前後空白を除去し、大文字小文字を区別せず一意とする。
- 在庫数は`0〜9999`の整数とする。
- 利用停止した道具は新しく作成する日別表へ含めないが、既存の日別表からは削除しない。

### 3.5 日付別チェック

- 管理者と作業者は日付を選び、チームで共有する1日1件のチェック表を閲覧できる。
- 今日または未来日の表は、初回アクセス時にその時点の有効な道具から冪等に作成できる。
- 過去日の表は閲覧専用とし、存在しない場合は新規作成しない。
- 日別項目には道具名、カテゴリ名、在庫数をスナップショットとして保存し、その後のマスター変更を自動反映しない。
- 管理者は作成済みの今日・未来日の表へ、有効な道具を重複なく手動追加できる。
- 持ち出し数は`0〜スナップショット在庫数`とし、チェックは持ち出し数が1以上の場合だけ付けられる。
- 持ち出し数を0へ戻すと、チェック状態も自動的に未チェックへ戻す。
- 操作ごとに自動保存し、楽観ロックで他ユーザーとの更新競合を検知する。

## 4. 権限表

| 機能 | 管理者 | 作業者 | 未認証 |
| --- | --- | --- | --- |
| ログイン、Refresh | 可 | 可 | 可 |
| 自分の情報・パスワード変更 | 可 | 可 | 不可 |
| ユーザー管理 | 可 | 不可 | 不可 |
| カテゴリ管理 | 可 | 不可 | 不可 |
| 道具マスター閲覧 | 可 | 可 | 不可 |
| 道具マスター変更 | 可 | 不可 | 不可 |
| 日別表の閲覧 | 可 | 可 | 不可 |
| 今日・未来日の表作成・更新 | 可 | 可 | 不可 |
| 作成済み日別表への道具追加 | 可 | 不可 | 不可 |

## 5. 非機能要件の概要

- 登録50ユーザー、同時20ユーザーを想定し、主要APIのp95を500ms以下、エラー率を1%未満とする。
- HTTPSを必須とし、パスワード、Token、Cookie、秘密値をログへ出力しない。
- 主要画面は360px以上で利用でき、WCAG 2.2 AA相当のラベル、キーボード操作、コントラストを考慮する。
- フロントエンド、バックエンド、DBをローカル・CI・本番で再現可能な構成にする。
- 詳細は[非機能要件](design/non-functional-requirements.md)を参照する。

## 6. MVP対象外

- 複数チーム・複数組織対応
- MFA、メール招待、本人によるパスワード忘れ対応
- チェック表の最終確定、誰がチェックしたかを表示する業務履歴
- 週間スケジュール、日報、通知、現場、保管場所、画像管理
- 道具の貸出・返却や、日別持ち出し数による在庫数の自動増減
- 検証環境、Multi-AZ RDS、ECSオートスケーリング、WAF

## 7. 受け入れ条件

- 未認証ユーザーは保護画面・保護APIへアクセスできない。
- 作業者が管理APIを呼ぶと`403 Forbidden`になる。
- 管理者は各マスターを管理でき、業務履歴を物理削除しない。
- 日別表の内容は作成時点で固定され、道具マスター変更後も過去・作成済み表が変わらない。
- 過去日の更新、在庫超過、0件でのチェック、古いバージョンでの更新が拒否される。
- 競合時に最新値を取得し直せる情報を`409 Conflict`で返す。
- 要件、画面、API、DB、テストが[トレーサビリティ表](design/traceability.md)で対応付けられている。
