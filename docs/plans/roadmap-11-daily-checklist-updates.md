# ロードマップ11 日別表の更新 実装計画

## 1. 目的

ロードマップ9・10で作成・表示できるようにした日別チェック表へ、持ち出し数量と準備状態の行単位自動保存、作成済み時間帯への作業カテゴリ追加、項目単位の楽観ロック競合からの復旧を接続する。

対応Issueは [#29 ロードマップ11 日別表の更新を実装する](https://github.com/Hiroyuki-12/FieldFlow/issues/29) とする。

## 2. Backend実装

### 2.1 日別項目更新API

- `PATCH /api/v1/daily-checklists/:date/periods/:period/items/:itemId`で、持ち出し数量、準備状態、画面が取得した`version`を受け取る。
- 日付、時間帯、項目IDが同じ現行`ACTIVE`表に属することを確認し、取消履歴の項目を誤更新しない。
- 持ち出し数量は0〜スナップショット在庫数の整数とし、数量0で`checked=true`を拒否する。数量を0へ戻す更新は`checked=false`と同じSQLで保存する。
- `WHERE id = :itemId AND version = :version`の条件付きUPDATEで成功した1件だけ`version`を増やす。更新件数0は後勝ち上書きをせず、409 `CHECKLIST_ITEM_UPDATE_CONFLICT`の`details.currentItem`へ最新行を含める。
- 現行ヘッダーを共有ロックしているTransaction内で項目を更新し、設定変更・削除と同時実行されても取消履歴へ入力が混入しないようにする。
- 管理者と作業者の両方へ公開し、過去日の更新は422で拒否する。

### 2.2 作業カテゴリ追加API

- `POST /api/v1/daily-checklists/:date/periods/:period/categories`で、有効な`WORK`カテゴリIDを1件以上受け取る。
- 対象時間帯をTransaction内でロックし、カテゴリスナップショットとそのカテゴリに現在属する有効な道具スナップショットを一括追加する。
- 選択済みカテゴリ、無効・`COMMON`・存在しないカテゴリ、既存項目と同じ元道具を拒否する。
- 共通道具は表作成時に追加済みのため再生成せず、`periodId + sourceCategoryId`と`periodId + sourceToolId`の既存一意制約をDBの最終防衛線として維持する。
- 成功時は追加後の日別表全体を返し、Frontendがカテゴリ・道具・進捗を同じレスポンスで同期できるようにする。
- 管理者と作業者の両方へ公開し、過去日の追加は422で拒否する。

### 2.3 DB方針

- `daily_checklist_items`には数量・準備状態・項目`version`・更新日時・数量境界CHECK制約がすでに存在する。
- `daily_checklist_period_categories`と`daily_checklist_items`には、時間帯内のカテゴリ・道具重複を防ぐ一意制約がすでに存在する。
- ロードマップ11で必要な永続化構造は初回Migrationに先行実装済みのため、新規Migrationは作らない。既存Migrationを書き換えず、結合テストで制約と更新SQLを検証する。

## 3. Frontend実装

### 3.1 API Client

- 項目更新APIとカテゴリ追加APIの型・関数を追加する。
- 共通`ApiError`へ安全な`details`を保持できるようにし、409応答の`currentItem`だけを画面復旧へ利用する。

### 3.2 数量・準備状態の自動保存

- 今日・未来日の道具行に数量の減少・増加ボタン、数値入力、準備チェックを表示する。過去日は現在どおり閲覧専用にする。
- 在庫境界外の値は送信せず、数量0では準備チェックを無効化して未準備へ戻す。
- 変更ごとに項目単位で保存し、`保存中`、`保存済み`、`保存失敗`を文字と色で表示する。
- 同じ項目への連続操作は項目別キューで直列化する。先の応答で得た新しい`version`を次の更新へ渡し、高速な連続クリックでも自分自身の409を起こさない。
- 通信失敗では画面上の値を保存済み扱いにせず、再試行ボタンと次の操作で保存を再開できる状態を残す。

### 3.3 409競合からの復旧

- 409 `CHECKLIST_ITEM_UPDATE_CONFLICT`では、編集中の値を破棄して`details.currentItem`の最新数量・準備状態・`version`へ置き換える。
- 「他のユーザーが更新しました」と通知し、最新`version`を使って利用者がそのまま再操作できるようにする。
- MVPでは自動マージやPush配信を行わず、競合した行だけを最新化する。

### 3.4 作業カテゴリ追加

- 今日・未来日の設定領域へ`作業カテゴリを追加`を表示し、現在選択中の時間帯に未追加の有効な`WORK`カテゴリだけを候補にする。
- ダイアログはロードマップ10と同様に、見出し・操作ボタンを固定し、候補部分だけをスクロールさせる。
- 追加後は返された日別表で画面を更新し、選択中の時間帯を維持する。
- 候補取得、選択済み競合、カテゴリ停止、別利用者による表変更、通信失敗を次の対応が分かる日本語で表示する。

## 8. 実装結果

2026-08-19にIssue #29の計画作成、Backend・Frontend実装、自動テスト、標準ポートでの疎通確認を完了した。

### 8.1 Backend・DB

- `PATCH /daily-checklists/:date/periods/:period/items/:itemId`を追加し、日付・時間帯・項目の所属を現行`ACTIVE`表まで照合してから数量と準備状態を更新するようにした。
- 現行ヘッダーの共有ロックと`WHERE id/version`の条件付きUPDATEを同じTransactionで実行し、項目更新と設定変更・削除の競合、および利用者同士の行更新競合を分離した。
- 数量0〜スナップショット在庫上限、数量0で準備済み禁止、過去日更新禁止をServiceと既存DB制約の両方で保証した。
- version不一致は409 `CHECKLIST_ITEM_UPDATE_CONFLICT`とし、`details.currentItem`へ最新行を返すようにした。
- MySQLの既定`REPEATABLE READ`では通常の再SELECTがTransaction開始時の古い行を返すことを結合テストで検出した。競合後だけロック付きcurrent readを使い、先行更新後の数量・準備状態・versionを確実に返すよう修正した。
- `POST /daily-checklists/:date/periods/:period/categories`を追加し、対象時間帯をロックして未選択カテゴリと現在有効な道具のスナップショットを一括保存した。
- 選択済み・無効・`COMMON`・存在しないカテゴリと、カテゴリ移動後などに起こり得る同一元道具の重複を拒否した。共通道具は再追加しない。
- 必要な項目`version`、数量・準備状態、更新日時、カテゴリ・道具一意制約、CHECK制約は初回Migrationに存在したため、新規Migrationは作成していない。

### 8.2 Frontend

- 日別項目更新とカテゴリ追加のAPI Client・公開型を追加した。
- 今日・未来日の道具行へ減少・増加ボタン、数値入力、準備チェックを追加し、数量0では準備チェックを無効化した。過去日の表示は閲覧専用を維持した。
- 道具ごとに独立した保存キューを設け、同じ行の連続変更を直列化した。先の応答versionを次の保存へ使うため、自分自身の高速操作で不要な409を起こさない。
- `保存中`、`保存済み`、`保存失敗`を文字と色で表示し、通信・サーバー失敗時は保存済み扱いにせず再試行できるようにした。
- 409の安全な`details.currentItem`を検証してから画面の該当行だけを最新値へ戻し、「他のユーザーが更新しました」と通知して再操作可能にした。
- 現在の時間帯に未選択の有効な作業カテゴリだけを表示する追加ダイアログを実装した。追加後は同じ時間帯を維持したままカテゴリ・道具・進捗を更新する。
- 項目の未保存・保存失敗が残る間は、カテゴリ追加・設定変更・削除を無効化し、構成変更で画面上の未保存値を失う事故を防いだ。

## 9. ロードマップ9〜11動作確認後の改善計画

2026-08-22の実画面確認で、データ整合性は要件どおり動作する一方、カテゴリ・道具が増えた場合の一覧性、競合箇所の視認性、スナップショット設計の説明に改善余地があることを確認した。Issue #29の追加範囲として次を実装する。

### 9.1 カテゴリ別アコーディオン

- カテゴリ見出し全体をbuttonにし、配下の道具一覧を開閉できるようにする。`aria-expanded`と`aria-controls`で支援技術へ状態を伝え、Enter・Spaceでも操作可能にする。
- カテゴリ見出しへ、持ち出し数量1以上を分母とした準備数・進捗率を表示する。分母0件は`持ち出し未設定`とする。
- `すべて開く`と`すべて閉じる`を用意する。
- 開閉状態は時間帯ごとに管理する。自動保存の応答では変更せず、午前・午後を切り替えても各時間帯の選択状態を維持する。
- 初回表示は既存画面と同じく全カテゴリを開く。カテゴリ追加時は既存カテゴリの状態を維持し、新しく追加されたカテゴリだけを開く。
- 保存失敗または競合が起きたカテゴリを自動的に開き、閉じた後もカテゴリ見出しへ警告を残す。

### 9.2 競合行の警告

- 409時の画面上部通知を残し、該当する道具行も警告色の背景・枠で強調する。
- 行直下へ、他ユーザーの更新で最新値へ戻したこと、最新数量・準備状態、再操作案内を`role="alert"`で表示する。
- 競合情報は短時間で消去しない。同じ道具を再操作した場合、または行の`閉じる`を押した場合だけ解除する。
- 競合時は該当カテゴリを開くが、自動スクロールは行わない。競合していない項目とその開閉状態は変更しない。

### 9.3 スナップショット説明

- 日別チェック画面へ、作成・設定変更時点のカテゴリ・道具・在庫数を保存しており、マスター変更は自動反映されないことを表示する。
- 最新マスターを取り込むには`時間帯・作業内容を変更する`から新版を作ることを案内する。
- カテゴリ追加ダイアログでは、選択カテゴリの現在有効な道具だけを追加し、共通道具は再取得しないことを説明する。
- 設定変更ダイアログでは、最新マスターから新版を作ること、旧版を取消履歴へ残すこと、同じ時間帯・同じ道具だけ入力を引き継ぐこと、方式変更では時間帯が変わるため入力を引き継がないことを事前表示する。

### 9.4 追加テスト

- カテゴリ単位の開閉、全開閉、`aria-expanded`、カテゴリ進捗を確認する。
- 自動保存後の開閉維持と、午前・午後で開閉状態が独立することを確認する。
- 保存失敗・競合時のカテゴリ自動展開と見出し警告を確認する。
- 409時の行内警告、最新数量・準備状態、行強調、閉じる／再操作による解除、他項目へ影響しないことを確認する。
- 日別画面、カテゴリ追加、設定変更に必要なスナップショット説明が表示されることを確認する。

## 10. 動作確認後の改善実装結果

2026-08-22に、9章の改善計画に沿ってFrontendの表示・状態管理・回帰テストを追加した。Backendの楽観ロック方式とAPI契約は変更せず、Roadmap 11で実装済みの409最新行レスポンスを利用した。

### 10.1 カテゴリ別アコーディオン

- カテゴリ見出しをbuttonに変更し、`aria-expanded`と`aria-controls`を設定した。ネイティブbuttonのため、クリックに加えてEnter・Spaceでも開閉できる。
- 見出しへカテゴリ単位の`準備 n / m・xx%`を表示した。持ち出し数量1以上だけを対象にし、対象0件は`持ち出し未設定`とした。
- `すべて開く`と`すべて閉じる`を追加した。小さい画面では見出し内の進捗を次の行へ折り返し、横方向にはみ出さない構成にした。
- 開閉状態は`FULL_DAY`、`MORNING`、`AFTERNOON`ごとに保持する。通常の自動保存では開閉状態を変更せず、カテゴリ追加時も既存カテゴリの状態を維持して新規カテゴリだけを開く。
- 保存失敗・競合が発生したカテゴリは自動的に開き、カテゴリ見出しの警告バッジと枠を、問題が解消されるまで表示する。

### 10.2 競合行の警告

- 画面上部の全体警告を維持し、競合した道具行へ背景・枠と`role="alert"`の行内警告を追加した。
- 行内警告には、Backendから返された最新数量・準備状態と、内容確認後に再操作できることを表示する。
- 警告は自動消去・自動スクロールしない。行の`閉じる`、または同じ道具の再操作で解除する。
- 競合した行だけへ最新値とversionを反映する。回帰テストでは、競合していない共通道具の値を維持し、最新versionで同じ行を再保存できることを確認した。

### 10.3 スナップショット説明

- 日別画面へ、作成・設定変更時点のカテゴリ・道具・在庫数を保存し、後からのマスター変更は自動反映されないことを常時表示した。
- 新規作成ダイアログでは、現在の作業カテゴリ・共通道具・在庫数を作成時点の内容として保存することを説明した。
- カテゴリ追加ダイアログでは、選択カテゴリの現在有効な道具だけを追加し、共通道具は再取得しないことを説明した。
- 設定変更ダイアログでは、最新マスターから新版を作ること、旧版を取消履歴へ残すこと、同じ時間帯・同じ道具だけ入力を引き継ぐこと、時間帯が変わる場合は引き継がないことを箇条書きで事前表示した。
