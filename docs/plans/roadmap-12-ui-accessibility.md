# ロードマップ12 UI・アクセシビリティ仕上げ 実装計画

## 1. 目的

ロードマップ5〜11で実装した全Frontend画面を、画面設計と操作確認用モックへ揃える。画面幅や入力方法にかかわらず、現在地、処理状態、エラー、次に行う操作を利用者が判断できる状態にする。

対応Issueは [#33 ロードマップ12 UI・アクセシビリティを仕上げる](https://github.com/Hiroyuki-12/FieldFlow/issues/33) とする。

ロードマップ13のBackendログ・セキュリティ強化は先行実装済みであり、本Issueではその共通エラーレスポンスを壊さず、Frontendの表示と操作を仕上げる。

## 2. 共通UI・画面遷移

- 本文へのスキップリンク、キーボードフォーカス、44px程度の操作領域を全画面で維持する。
- ナビゲーションは現在地を文字・背景・`aria-current`で示す。モバイルメニューはEsc、リンク選択、画面遷移で閉じ、閉じた後はメニューボタンへフォーカスを戻す。
- 画面遷移時はスクロール位置を先頭へ戻し、画面見出しへフォーカスを移して、支援技術とキーボード利用者へ遷移を伝える。
- 成功、警告、失敗、読込中を色だけに依存せず、アイコン、見出し、本文、必要な再試行操作で表す。
- ログイン、パスワード変更、管理フォームの入力エラーを対象項目と`aria-describedby`・`aria-invalid`で関連付ける。

## 3. ダイアログ

- ネイティブ`dialog.showModal()`を使い、背景を操作対象外にしてフォーカスをダイアログ内へ保つ。
- 開いた直後は見出しまたは最初の入力へフォーカスし、Escとキャンセル操作で閉じられるようにする。
- 閉じた後は、ダイアログを開いたボタンへ明示的にフォーカスを戻す。
- 保存中は誤って閉じられないようにし、失敗時はダイアログを保持して再操作できるようにする。
- 小さい画面では本文だけをスクロールし、見出しと操作ボタンを表示領域に残す。操作ボタンは狭い幅で縦並びにし、横方向へはみ出さないようにする。

## 4. レスポンシブ

- 360pxをモバイル、768pxをタブレット、1280pxをPCの代表幅として確認する。
- 管理一覧はモバイル・タブレットでカードを使い、十分な幅があるPCだけテーブルを使う。
- 日別チェックの道具行は、道具名、数量、準備状態、保存状態の順序を保ち、360pxで2行以内を基本とする。
- 長い利用者名、カテゴリ名、道具名、仮パスワード、エラーメッセージがページ全体の横スクロールを起こさないようにする。
- ダイアログの高さは動的Viewportを基準にし、ソフトウェアキーボード表示時も見出しと操作領域へ到達できるようにする。

## 5. 画面別仕上げ

- ログイン・パスワード変更: 項目別エラー、送信状態、通信・認証失敗、初期フォーカスを明確にする。
- ホーム: 今日の状態、空状態、通信失敗と再試行、別日選択、管理ショートカットを整理する。
- 日別チェック: モバイルでは設定を折りたためるようにし、道具一覧を優先する。既存の自動保存・競合・カテゴリ開閉の状態表示を維持する。
- ユーザー・カテゴリ・道具管理: 絞り込み、空状態、一覧、ページ移動、作成・編集・状態変更ダイアログを同じ操作規則へ揃える。
- 403・404・セッション切れ: 原因と安全な戻り先を1つの主操作として示す。

## 6. テスト計画

- Router・共通レイアウトのテストで、現在地、モバイルメニューのEsc・遷移時閉鎖、画面先頭へのフォーカス移動を確認する。
- 認証画面のテストで、項目エラーの関連付け、送信中の無効化、通信エラー通知を確認する。
- 各ダイアログのテストで、初期フォーカス、Esc、起点へのフォーカス復帰、保存中の閉鎖防止、エラー後の再操作を確認する。
- 管理画面と日別画面のテストで、状態を表す文字、空状態、再試行、折りたたみのアクセシブルな名前と状態を確認する。
- 実ブラウザで360px・768px・1280pxを確認し、ページ全体の横スクロール、フォーカス表示、キーボード操作を確認する。

## 10. 実装結果

2026-08-22にIssue #33の計画作成、Frontend実装、設計資料更新、自動テスト、未認証画面の実ブラウザ確認を完了した。

### 10.1 共通ナビゲーション・画面遷移

- 現在のナビゲーション項目を、背景・文字色とVue Routerの`aria-current="page"`で示すようにした。
- モバイルメニューを開いた直後は最初のリンクへフォーカスし、Escで閉じた後はメニューボタンへ戻すようにした。リンク選択や別画面への遷移でもメニューを閉じる。
- Routerの`scrollBehavior`で画面先頭へ戻し、DOM更新後に`data-page-heading`を持つ主見出しへフォーカスするようにした。表示内容が変わっても前画面の操作位置へフォーカスが残る事故を防ぐ。
- ログイン画面は主見出しを「ログイン」の1件へ整理し、紹介コピーは`h2`にした。

### 10.2 ダイアログ・入力・通知

- `useModalDialog`へ初期フォーカス、Tab／Shift+Tabの循環、閉じた後の起点復帰を共通化した。ネイティブ`showModal()`と組み合わせ、背景操作を防ぐ。
- 日別表作成、設定変更、カテゴリ追加、削除、ユーザー・カテゴリ・道具の管理ダイアログへ共通処理を適用した。保存中は既存どおり閉鎖操作を拒否する。
- 小さい画面ではダイアログ操作ボタンを縦並びにし、480px以上で横並びへ戻す。高さは動的Viewportの90%以内とし、本文をスクロール可能にした。
- 成功、警告、失敗、情報をアイコン・見出し・本文・ARIA Live Regionで示す`AppNotice`を追加し、共通レイアウト、ホーム、日別チェック、3管理画面へ適用した。
- ログイン、パスワード変更、3管理ダイアログのエラーを`aria-invalid`と`aria-describedby`で入力へ関連付けた。エラーは`role="alert"`で通知する。

### 10.3 レスポンシブ・操作領域

- 画面全体の意図しない横方向Overflowを抑止し、長い名前・エラーが折り返されるようにした。
- ユーザー管理は360pxと768pxでカード、1280px相当の十分な幅でテーブルを使う。タブレットで表内横スクロールへ依存しない。
- 日別チェックの日付・時間帯設定を、モバイルでは`aria-expanded`付きで折りたためるようにした。768px以上では常時表示する。
- 日別チェックの数量増減、入力、準備操作、カテゴリ全開閉を44px以上へ揃えた。
- フォーカス対象をbutton・link・inputだけでなくselect・textarea・プログラムで移動する見出しまで広げ、色だけに依存しないフォーカス枠を表示する。
- `prefers-reduced-motion`ではスクロールとTransitionをほぼ無効化する。

### 10.4 自動確認結果

- Frontend: typecheck、lint、17 suite・77件のVitest／MSWテスト、build成功。
- 追加テストで、モバイルメニューの初期フォーカス・Esc・起点復帰、現在地、画面遷移後の見出しフォーカス、入力エラー関連付け、日別設定の開閉を確認した。
- 共通ダイアログの回帰テストで、初期フォーカス、閉鎖後の起点復帰、Tab／Shift+Tabの循環を確認した。

- このRepositoryのFrontend `5173`、Backend `8080`、MySQL `3306`が規定portを使用していることを確認した。
