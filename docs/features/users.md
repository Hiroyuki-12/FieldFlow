# ユーザー管理機能定義

## 目的

管理者がチームの利用者と権限を安全に管理し、退職・異動後も履歴を壊さず利用を停止できるようにする。

## 入力制約・管理項目

| 項目 | 制約 |
| --- | --- |
| 名前 | 1〜100文字、前後空白を除去 |
| ログインID | 4〜50文字、半角英数字と`._-`、大文字小文字を区別せず一意 |
| ロール | `ADMIN`または`WORKER` |
| 状態 | `ACTIVE`または`INACTIVE` |
| 初回変更要否 | システム管理、作成・再発行時は`true` |

## 正常系

- 管理者は一覧検索、作成、編集、利用停止、再有効化、仮パスワード再発行を行える。
- 一覧は名前・ログインID検索、ロール・状態絞り込み、ページングを提供する。
- 作成・再発行のレスポンスだけに仮パスワードを含め、画面を閉じる前に共有するよう注意を表示する。
- 利用停止と仮パスワード再発行は`authVersion`を更新し、対象ユーザーのAccess TokenとRefreshセッションを全端末で失効する。

## 異常系・保護ルール

- 作業者からの管理API呼び出しは`403`とする。
- 最後の有効な管理者は利用停止・作業者への変更をできない。
- 管理者は自分自身を利用停止・作業者へ変更できない。
- 存在しない対象は`404`、ログインID重複は`409`とする。

## 受け入れ条件

- 利用停止したユーザーは新規ログインも既存セッション利用もできない。
- ユーザーを物理削除せず、作成日時・更新日時を保持する。
- 同時更新では古い`version`を拒否し、意図しない上書きを防止する。
